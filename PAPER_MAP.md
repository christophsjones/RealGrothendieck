# Paper-to-code map

This map describes how the analytical reductions correspond to the numerical verifications, following the v1 arXiv version of the paper. It covers the numerical assertions in the lower-bound appendix (Appendix B) and upper-bound appendix (Appendix C, especially C.5). The analytic reductions and proofs remain in the paper; the programs check their finite numerical hypotheses. The equations below are labeled using their label names in the LaTeX source.

The [rounding](rounding/) directory describes the rounding algorithm output by the primal/dual run in Appendix A.

All source and input paths below are relative to the repository root. Run the root `verify.py` to check the manuscript's complete numerical conditions. The `--data-only` mode checks file identities and exact finite input conditions, including the rational rotation-tail check; it does not execute either numerical proof.

For a successful root run, let `RUN` denote its new `runs/complete-*` directory. If `--output` is supplied, that parent replaces `runs/`. The tables abbreviate:

- `L = RUN/lower_results`.
- `U = RUN/upper_results/run-*/work/certification` (there is exactly one fresh upper run).
- `S = upper/source/certification` for upper source paths.

`RUN/ACCEPTED.json` is written only after all requested numerical computations and the root wrapper's final manuscript comparisons succeed. Lower-only or upper-only acceptance means exactly the requested side passed. A data-only invocation does not produce numerical acceptance. Files under `runs/` are regenerated outputs, not distributed proof inputs.

## Lower bound: 35 rows at 384 bits

The numerical conclusion is

`v_n(q) <= v_* = 999999998227/1773000000000`

for every dimension, which gives `K_G >= 1773000000000/999999998227 > 1773/1000` through the paper's one-variable criterion and duality.
